# 降雨优先的时序门控与动态 loss 设计

日期：2026-10-19。状态：用户已确认按本设计实现；实现使用独立文件，服务器资源与预测性能仍需实测。

用户已确认：降雨预测是主任务，雷达和卫星预测是辅助任务。保留原网络主体、原 3D decoder 和四帧历史预测四帧未来的协议，研究范围集中在门控和 loss。本文中的新系数与更新周期是待验证的实验起点，不是已证实的最优参数。

## 1. 要解决的具体问题

当前空间门控只看逐帧特征，用所有模态的预测损失共同训练；它没有专用的门控监督，也不知道输入是真值供给还是 rollout 生成。一个有利于卫星自身重建的融合系数，不一定有利于未来降雨预测。这是需要检验的目标冲突假设，不能仅凭图像模糊认定已经发生了模态串扰。

已有审计确认了更直接的 loss 问题：某些残差监督与雨量像素误差重复；在预测历史有偏差时，rollout 的真值增量监督可能与当前雨量纠偏冲突；原 `mse` 路径并未实际使用配置中的 `rain_region_weight`。这些问题应先从新实验目标中消除，再评价动态加权的增益。实施范围与验证结果见 [本次实现记录](../../codex_changes/2026-10-19-降雨优先门控与动态损失.md)。

本方案的研究假设是：门控以降雨预测为目标，并知道局地演变及输入来源；loss 根据实际 rollout 的各时效表现分配有限的训练权重。这可能改善误差随时效累积的问题，但不保证 CSI 提升，也不保证卫星输出变清晰。

## 2. 固定边界与未解决的前置问题

| 项目 | 本设计约束 |
| --- | --- |
| 主网络 | 原 patch embedding、ConvStem、时空 Transformer、三个原 3D decoder 保留；不切换到 2D |
| 数据与时间 | 当前 30 分钟数据，四帧历史、四帧未来，即 +30/+60/+90/+120 分钟；不改训练/验证月份、筛选或增强 |
| Teacher forcing | 恢复并保留原右移 sequence 训练：八帧组成七个 next-frame 监督位置；历史三位置和未来四位置分别平均、等权组合 |
| Rollout | 保留固定起报的四步自回归，`detach_history=true`，不注入真实未来雷达、卫星或降雨 |
| 残差参数化 | 保留“上一帧雨量 + 预测增量”的输出方式；取消重复或冲突的辅助增量 loss，不取消残差输出 |
| 创新点范围 | 保留独立门控框架与 I/O 优化；adapter、CCC、local refiner、GAN 本轮不额外启用 |
| 验证 | 允许打乱顺序；可比较的正式结果使用同一验证集合。随机小子集结果只能作为过程监测 |
| 文件与运行 | 不改写 baseline、同学快照或已有实验文件；新实现须使用独立文件；不改正在运行的服务器实验 |

原 3D decoder 已在前缀扰动检查中暴露时间填充/归一化方面的因果性问题，且 teacher forcing 与 rollout 的解码时间长度不同。保留原结构并不会让这些问题消失。新增门控自身必须通过因果性测试；完整旧网络的已知失败必须保留报告。最终将效果归因于新门控/loss 前，需要另行确定这一既有问题的处理或控制实验，不能悄悄改 decoder，也不能宣称本方案已完成因果性修复。

训练中原本就存在的 teacher forcing 可以供给真实前序帧；这些输入不等同于固定起报推理时可获得的观测。新门控只能读取所在前向调用已经允许的输入前缀与元数据，不能额外读取该位置的目标标签。

## 3. 方案比较与选择

| 方案 | 优点 | 限制 | 决定 |
| --- | --- | --- | --- |
| 各预测时效的有界误差反馈 + 降雨目标门控 | 不增加预测头；权重可解释；适合先排查现有目标问题 | 误差反馈不等于直接优化 CSI；门控梯度分流仍有反向计算开销 | 推荐第一版 |
| 基于梯度的多任务动态平衡 | 可直接测量/调整不同任务对共享网络的训练影响 | 通用任务平衡不自动表达降雨优先；额外求梯度需要实测显存和吞吐 | 作为对照或后续方案 |
| 同时学习每像素、每模态、每时效的任意 loss 权重 | 灵活 | 权重可能通过压低困难样本的重要性来降低目标；难以解释哪个设计生效 | 第一版不采用 |

已有 DWA 利用 loss 的变化调整任务权重，GradNorm 则依据梯度量进行动态平衡。这支持把数值反馈和梯度反馈作为两种可比较的设计；本文的按时效反馈是项目适配方案，不宣称其本身构成新的通用算法。[DWA/MTAN 原论文](https://arxiv.org/pdf/1803.10704)、[GradNorm 原论文](https://proceedings.mlr.press/v80/chen18a.html)。

多模态优化失衡在其他任务上已有研究，但这并不能直接证明当前降雨模型发生了同类失衡。门控和梯度统计需要在本项目上验证。[OGM-GE 原论文](https://arxiv.org/abs/2203.15332)。

## 4. 第一版 loss：先把每个监督目标定义清楚

令模态 m 属于 {rain, radar, satellite}。`e_m,j^TF` 是第 j 个 teacher-forced 位置的像素 MSE，`e_m,h^AR` 是固定起报 rollout 的第 h 帧像素 MSE。各模态内部对 batch、有效像素及自己的通道取均值，不能把十个卫星通道当成十份任务 loss。第一版均采用原数据数值空间，不新增归一化或输出裁剪。

原 sequence 分段方式保持为：

```text
L_m^TF = 0.5 * mean(e_m,1^TF, e_m,2^TF, e_m,3^TF)
       + 0.5 * mean(e_m,4^TF, e_m,5^TF, e_m,6^TF, e_m,7^TF)
```

第一版推荐的总目标：

```text
L_rain = L_rain^TF + rho * sum_h(q_h * e_rain,h^AR)
L_radar = L_radar^TF + rho * mean_h(e_radar,h^AR)
L_satellite = L_satellite^TF + rho * mean_h(e_satellite,h^AR)

L_total = L_rain + beta_radar * L_radar + beta_satellite * L_satellite
```

提出 `rho=0.2` 作为沿用原 rollout 权重的起点，`beta_radar=beta_satellite=0.1` 作为降雨优先的实验起点。辅助模态仍接受四步 rollout 监督，因为它们生成的图像会成为后续输入；相比最早的 3D 实验仅对 rollout 降雨计 loss，这是明确的监督范围调整，不是 decoder 或帧数调整。所有新的对照组使用相同辅助监督范围。

这些系数只是标量优先级，不保证共享参数上的降雨梯度一定大于辅助梯度。需同时记录各任务共享参数梯度范数及夹角，再决定是否降低辅助预算；不能凭标量 loss 占比判断串扰。

本轮先固定模态间系数，仅动态更新四个降雨预测时效权重。这样可以区分“哪个未来时效需要更多训练”和“哪个模态任务应该让步”，避免两个控制器同时变化导致无法归因。

第一版不叠加原 `rain_residual.delta_weight`、rollout 真值增量辅助项或原雷达引导 temporal-diff 项。它们从独立新实验目标中排除，原实现和旧实验记录保留。第一版也不声称启用了强降水加权、事件辅助 loss 或新的平滑约束。

## 5. 动态时效权重的完整更新规则

动态权重控制的是训练期间模型自己做出的四步 rollout，不是未来尚未获得的观测，也不读取验证/测试结果。控制器使用训练标签计算误差完全合法；这些标签不能进入预测或门控的前向输入。

1. 初始 `q=[0.25, 0.25, 0.25, 0.25]`，前 1000 个成功 optimizer step 保持均匀。只用第 801—1000 步统计各时效的未加权雨量 MSE，得到冻结参考 `b_h`，避免把初始化最差时的误差用作长期参照。
2. 此后每 200 个成功 optimizer step 汇总一次未加权误差。按误差总和/有效元素数求窗口均值 `u_h`，不能对大小不同的 batch 简单求平均。
3. 设 `E_h=b_h` 为初始平滑误差，此后更新 `E_h=0.8*E_h+0.2*u_h`。所有控制器统计用 FP32、脱离 autograd，且始终使用加权前的误差。
4. 相对误差、建议权重定义如下：

```text
r_h = clip(E_h / max(b_h, eps), 0.25, 4.0)
p_h = softmax(log(r_h) / T)
q_h = (1 - alpha) / 4 + alpha * p_h

eps = 1e-6, T = 1.0, alpha = 0.5
```

5. 新权重从下一个训练窗口生效，不追溯改变刚刚统计的 loss。参考值非有限时停止并报告；某个时效参考误差小于 `eps` 时，该时效的相对误差置为中性值 1 并记录告警，避免除极小值后占据权重。

因此始终 `sum(q)=1`，且每个时效权重在 `[0.125, 0.625]` 内；这是保守数学边界，ratio 截断会进一步收紧实际范围。总权重预算不变，任一预测时效都不会被关闭。

这里强调的是“相对自己的参考，哪些时效改善更少或发生退步”，不直接把绝对误差最大的远期帧永远设成最大权重。例如相对误差为 `[0.5,0.5,1,1]` 时，权重约为 `[0.2083,0.2083,0.2917,0.2917]`。如果四个时效同比例改善，权重仍均匀。

这与原 DWA 的相邻统计周期 loss 比值不相同；本文采用冻结参考、EMA 与均匀分量约束，便于控制长期时效偏差。它是待验证的控制规则，不是从论文直接获得的最优配置。

控制器只改变 loss 的训练系数，不产生可学习参数。保存 checkpoint 必须包含参考值、EMA、当前 q、窗口累计误差/计数、初始化状态及成功 optimizer step；恢复后在相同输入序列上，下一次权重更新应与不中断运行一致。未来支持多卡时，统计先全局聚合，再在各卡使用相同 q；第一轮服务器验收限定单卡 BF16。

CSI、FAR、POD 同步记录，但第一版不把单个小 batch 的 CSI 直接转换成 loss 权重。稀疏降雨下其分母和阈值跳变可能很大；更不能对硬阈值 CSI 直接反向传播。后续若尝试 CSI 反馈，须单独定义窗口事件计数和零分母规则，作为独立消融。

## 6. 门控：利用局地演变和输入来源，服务于降雨

保留现有的插入位置和融合形式：共享 patch embedding 之后、ConvStem 之前。仍复用原 patch 卷积权重的雷达/卫星/降雨切片计算 `z_R,z_S,z_P`；不新建三个主编码器，也不改三个输出 decoder。

```text
g_R = 1 + tanh(a_R)
g_S = 1 + tanh(a_S)

z_fused = z_base + (g_R - 1) * z_R + (g_S - 1) * z_S
```

两个门控各自位于 `(0,2)`，输出层零初始化时均为 1。历史降雨直接通路的系数仍为 1。雷达和卫星可以同时被使用，不强迫两者通过 softmax 竞争一个总和为 1 的预算；这里的 gate 也不是置信概率。

建议新门控相对旧版增加以下条件：

| 输入信息 | 来源与作用 |
| --- | --- |
| 三模态当前局地特征 | 当前输入图像经原 patch 权重得到；保留雨量对雷达/卫星选择的条件作用 |
| 三模态因果变化量 | 当前特征减去严格前一输入时刻的特征，帮助区分稳定背景与局地发展/衰减 |
| 来源标记 | 每个模态明确标记为真值供给、模型生成或缺失，区分历史观测与递推结果 |
| 相对起报时间 | 已知时间索引，区分历史和生成帧；不来自未来天气真值 |

门控条件特征可做逐 token、沿通道的归一化，再计算向后差分；原参与融合的数值特征不做额外归一化。禁止跨时间统计的归一化和中心差分。新门控仍采用小型逐帧空间网络：`1x1 Conv → SiLU → 3x3 depthwise Conv → SiLU → 1x1 Conv`，hidden=32，输出两个空间图。

来源标记由 trainer 根据实际使用的输入生成，不能用“像素等于零”推断缺失。Teacher forcing 的真实前序帧应标为真值供给，rollout 拼回的预测帧应标为模型生成，即便数值恰好相同也不能混淆。这个标记表示数据来源，不宣称生成帧一定不可信。

变化量需要对齐原输入时间轴：首个无前序的输入使用零差分和无前序标记；缺失帧或非连续时间之间不能伪造有效差分。context/seed 的重复边界不能被当成新的物理时间步。门控所需的前序信息只能取自允许的输入前缀，再随原切片传入；不能为计算差分而编码目标帧。所有新增元数据在正常 rollout 推理时必须可获得。

当前十个卫星通道仍共享一个门控。通道的物理含义尚未核实，因此本轮不手工指定“某个通道就是对流先兆”，也不硬编码卫星权重应随预测时效增加。

这项改动让门控具备时序条件，但并不赋予它显式风场平流、跨模态配准或质量标定能力。56×56 token 级变化也不等价于逐像素气象运动。

## 7. 门控 loss 与梯度流：明确而非只改名字

第一版不另造一个熵 loss、均衡 loss 或“必须偏好某种模态”的伪标签。门控的任务目标就是上一节定义的 `L_rain`，包括原 sequence 的降雨监督与动态加权的四步降雨 rollout。

令 `theta_gate` 仅表示门控条件网络的新增参数，`theta_rest` 表示其他参数：

```text
grad(theta_gate) = d L_rain / d theta_gate
grad(theta_rest) = d L_total / d theta_rest
```

这不是把 `L_gate=L_rain` 再加一遍到总 loss 中。若对 `L_total` 直接 backward，辅助损失仍会更新门控；如果只是 detach 门控输出，又会误切断正常降雨监督。因此需要独立 trainer 显式构造两组正确梯度，验证后再接入优化器。

辅助任务仍训练共享 patch 权重、主干和自己的 decoder。共享特征变化会间接影响门控，所以不能把此设计称为完全消除模态串扰。原全局 gradient clipping 若保留，其统一缩放也会影响门控梯度大小；“辅助目标不直接更新门控”的严格数值测试应比较裁剪前梯度，不夸大为训练动力学完全独立。

验收时，保持相同前向结果，仅改变雷达/卫星辅助 loss 系数，裁剪前门控梯度应不变；改变降雨目标，门控梯度应相应改变。门控输出层零初始化时，内部层首步梯度为零可以是正常现象，第二步之后应能学习。

独立 trainer 必须正确处理梯度累积、BF16/缩放、activation checkpoint、非有限梯度及 optimizer step。不得用原框架运行时替换或隐藏 hook 改写旧实验。多一次针对门控的向量-雅可比反向计算可能经过大部分主干；参数少不代表耗时低，不能承诺 24GB 上没有额外开销。

## 8. 更进一步的事件与演变监督：分开验证

动态 MSE 仍然是 MSE；它不自动对齐 CSI，也不保证生成清晰的小尺度回波。第一版验证通过之后，再分别测试以下两条路线，每次只增加一项，不在第一次长训练中同时启用。

**事件监督。** 在同一雨量输出上，用 `sigmoid((prediction-threshold)/temperature)` 对应真值是否越过阈值，构造正/负区域分别平均的二元交叉熵。无雨负样本不能被屏蔽，防止只提高 POD 却扩大虚警；某个区域为空时只对存在的区域求平均。保持现有 0.1/0.3/0.5 数值阈值作为评估参照，先核实它们对应的数据数值空间和累计时间，不能直接标成 mm/h。该 sigmoid 值只是训练代理，不宣称是校准后的概率。事件温度、系数和相对于像素 loss 的梯度预算需要独立小实验确定，第一版默认关闭。

**真正的多帧演变监督。** 如引入相邻差分，只从第二张未来帧开始定义：

```text
L_evolution = mean over h=2..4 of
    abs((rain_pred_h - rain_pred_(h-1)) - (rain_gt_h - rain_gt_(h-1)))
```

它比较两张最终预测雨量图的变化，不对内部 residual delta 施加使用另一条历史的目标。第一个预测位置对同一真实历史做差会退化为像素误差，因此不再次计入。rollout 的输入历史仍按原设置 detach；演变 loss 对两个保留的输出 tensor 求导，不额外 detach 前一个输出。这两个 detach 位置不能混淆。

演变项同样可能与绝对雨量误差争夺梯度，且仅约束变化不能消除恒定偏差。其系数第一版为 0，只有独立消融显示逐时效 CSI/FAR 和雨量误差改善时才保留。不能把“有时间差分”直接称为正确的物理约束。

## 9. 实验顺序与判定标准

先做工程/数学验收，再做短实验；无需直接投入另一轮 100000 步。所有比较使用同一原 3D 网络、四进四出、数据分布、优化器、样本预算和评价程序。新实验从头初始化，不将 2D checkpoint 当成原 3D 完整续训状态。

建议按以下递进设置进行比较，已有失败长实验只作背景证据，不能替代公平的对照组：

| 组别 | 与上一组相比唯一改变 | 要回答的问题 |
| --- | --- | --- |
| A | 无空间门控，清理后的固定权重 loss | 理顺目标后，原网络能否学习并超过持久性预测 |
| B | 增加旧空间门控，仍由所有任务监督 | 旧门控在同一干净目标下是否有效 |
| C | 旧门控只接受降雨 loss 梯度 | 辅助任务直接影响门控是否不利 |
| D | 换成带向后变化量、来源和时间条件的新门控 | 项目专用条件是否有帮助 |
| E | D 加动态四时效权重 | 动态分配是否进一步改善远期预测 |
| F | C 加动态四时效权重，与 D/E 组成局部 2×2 对照 | 新门控条件与动态 loss 是否存在配合收益 |

不要求立即六组全长训练。先依次验证 A/B/C；有可比较信号后继续 D/E，F 用于判断两项改动的交互作用。任一阶段出现非有限 loss、不能拟合小样本或完全不使用历史信息时，先定位该阶段，不叠加更多模块。小样本拟合只是工程检查，尤其在已知因果风险下不能充当泛化证据。

工程阶段采用 20 步 smoke、单个训练 batch 的 200—500 步拟合检查和断点恢复。首轮受控比较可使用每组 2000—6000 步的相同预算；这只筛选明显失效方案，不能据此承诺最终收敛时刻。若有效学习率、实际样本数或每步耗时变化，要同时报告，不只比较 step。

固定起报评价至少报告：

- 每个时效、每个阈值的 CSI、FAR、POD；先聚合命中/虚警/漏报计数，再计算指标，零分母单独记录。
- 各时效雨量 MAE/MSE、预测湿区比例、真值干区上的预测雨量均值/分位数；与最后一张历史雨量复制四次的持久性基线比较。
- 原日志的指标口径可以保留供连续查看；新全量计数口径要独立命名，不混成一条历史曲线。
- 同一组样本的原始预测对比图；不把可视化 Gaussian blur 的结果拿来计算指标；同一模态各时效使用统一色标。
- 门控在真值供给/生成输入、不同降雨区域的分布、接近边界的比例、实际特征贡献范数；大 gate 不自动解释为高可靠性。
- 分任务共享参数梯度范数、夹角、门控梯度范数及 q 的轨迹；低频诊断另计耗时，不能拿标量 loss 占比代替梯度证据。

验证可以随机顺序遍历全部样本。比较结论须来自同一集合、同一聚合定义；若需要不确定性估计，按天气事件或时间块重采样，不能把高度重叠的滑窗当作独立样本。正式“有效”的判断应基于预先选定的平均 CSI、远期 CSI 以及 FAR/POD、MAE/MSE 的联合结果，避免只挑最好的阈值或一张图。

对已发现的完整旧网络因果性问题，以上实验仍需显式记录限制；短对照有诊断意义，最终收益归因和正式训练方案不能跳过这一待决项。

## 10. 实现边界与验收合同

实现采用独立模型/门控文件、loss/controller、trainer、入口和 YAML，复用允许复用的原模块，保留原目录内现有文件。文件拆分见实现计划；实际入口与 CLI 见 [num8 操作步骤](../../experiments/2026-10-19-rain-priority-num8.md)。

| 验收项 | 预期结果 |
| --- | --- |
| 原结构 | decoder 类、参数形状和帧协议不变；门控关闭时模型与原网络等价 |
| 初始门控 | g=1 时前向与同权重原网络一致；bias 只计一次 |
| 新门控因果性 | 改动较晚输入/目标不改变较早门控；输入时间错位或非法来源标记显式失败 |
| 固定起报隔离 | 只改变未来真值，四步预测保持不变；预测后计算的 loss 和下一窗口 q 允许改变 |
| 残差纠偏 | 历史预测偏高、当前真值为零的反例中，直接雨量 loss 的梯度推动修正偏差，不混入旧 GT 增量项 |
| Loss reduction | 每个模态/时效的数值可手工复算；相同输出在 q 均匀时等于普通四帧均值；配置中关闭的 loss 确实不计算 |
| Controller | 权重和、上下界、窗口更新时间、全零参考、非有限输入、恢复一致性均有测试 |
| 梯度路由 | 辅助 loss 不直接改变裁剪前门控梯度；主干和辅助 decoder 正常收到各自目标的梯度 |
| 数值与存储 | FP32 小模型检查、BF16 服务器 smoke、保存重载、梯度累积和 activation checkpoint 检查 |
| 资源 | num8 实测 batch1，再测 batch2；报告峰值 allocated/reserved 与吞吐，保留显存余量 |

4090 只有 24GB，旧 3D batch2 已记录峰值 reserved 约 22.74GiB，因此不能预先保证新条件特征与额外反向过程仍容纳 batch2，更不建议直接上 batch4。若需要降低 micro-batch，比较组应保持同一有效 batch 和样本预算，并重新验证梯度累积一致性。

pytest 放在 `src/tests/` 对应分类；不跑 ty。模型正确性、工程可运行和预测性能改善是三个独立验收结论，不能用其中一个替代其他两个。

## 11. 当前结论与审阅状态

本次确定的是“降雨优先”的研究目标。推荐先建立清理后的 loss 对照，再单独验证降雨梯度门控、时序/来源条件和有界时效反馈。事件 loss、演变 loss、梯度平衡都保留为有明确比较问题的后续实验，而不是一次性叠加。

用户随后确认“根据你的设计修改代码”，授权实施和提供服务器同步、实验启动方法。实现保持原文件和运行中的训练不变。原 3D decoder 因果性问题如何单独处理，仍是正式性能结论前必须讨论的未决事项。
