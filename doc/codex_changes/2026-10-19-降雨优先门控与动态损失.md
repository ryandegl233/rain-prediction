## 目标函数与反馈含义

每个模态的 teacher-forcing 目标为历史 3 个 next-frame 位置 MSE 的均值乘 0.5，加未来 4 个位置 MSE 的均值乘 0.5。降雨目标再加 `0.2 * sum(q_h * rollout_rain_MSE_h)`；雷达/卫星目标各加 `0.2 * mean(rollout_MSE_h)`。总目标：

`L_total = L_rain + 0.1 * L_radar + 0.1 * L_satellite`。

保留“上一帧雨量 + 预测增量”的输出参数化；新入口不计算旧 delta 辅助项、旧 temporal-diff、雨区加权、事件损失和 GAN，不把关闭的配置打印成正在生效的损失。辅助目标仍训练共享主干和各自 decoder。

前 1000 个成功 optimizer step 使用 `q=[.25,.25,.25,.25]`。801–1000 步形成各时效参考误差；其后每 200 步更新一个 EMA 窗口（衰减 .8）。相对参考误差裁剪到 [.25,4] 后，计算 `q=.125+.5*softmax(log(r)/T)`，`T=1`。四项之和为 1，每项在 [.125,.625]；新的权重从下一次训练调用生效。统计按像素数加权、detach、CPU FP32 保存，只来自训练 rollout。验证不更新 q；零参考时效使用中性比率并告警。

这属于按预测时效分配有限权重，并不是任意像素动态 loss，也不是直接优化 CSI。实际预测收益必须通过对照实验检验。

## 门控与时序协议

新门控继续使用原 patch 权重分解的三个模态贡献。雷达/卫星系数为 `1+tanh(logit)`，范围 (0,2)，初始化为 1；降雨贡献系数保持 1，bias 只计算一次。因此同权重初始前向与原 3D 网络一致。

门控读取归一化当前特征、因果向后差分、来源 one-hot 和相对时间。重复的 context/seed 使用相同时间标记；差分只取此前真实相邻时刻，不能拿重复 seed 相减冒充演变。新 trainer 校验原数据集提供的 float64 绝对时间戳，允许正常 +1800 秒及原反向增强 -1800 秒，拒绝重复/短间隔/断档。模型启用 temporal gate 时必须显式传 `gate_source` 与 `gate_steps`。

4 帧历史 / 4 帧未来、右移 7 目标训练和固定起报四步自回归均保留；生成历史 detach；推理不使用真实未来天气。旧 dropout、时间反向等数据增强保持继承配置。

门控的直接梯度单独由 `L_rain` 计算；主干与 decoder 接收 `L_total` 梯度。已有 micro-batch 梯度被正确保留，避免辅助 backward 覆盖雨量专属累计梯度。全模型裁剪仍会通过整体系数间接影响门控步长，因此不宣称完全消除模态间的训练影响。

## 评价与日志口径

验证默认随机顺序遍历完整验证集合，先累计 hits/false alarms/misses，再计算每个时效和全时效 CSI/FAR/POD。零分母为 JSON `null`，不会伪装成 0 或 1。输出每时效 MAE/MSE、预测/真值湿区比例、真值干区预测均值，以及复制最后历史帧的 persistence 指标。新指标不能与旧随机 60-batch / 不同聚合方式混画成同一条趋势。

干区为真值低于最小配置阈值。分位数使用固定直方图近似：[-1,2] 内步长 .001，报告 p50/p90/p99 的桶中点；尾部额外报告 underflow/overflow 比例，分位数落入尾部时为 `null`。没有把异常大雨量裁掉再报告好看的分位数。该统计空间沿用现有 rain metric space，不擅自标为 mm/h。

门控记录总体均值、饱和比例、贡献 RMS，并按缺失/真值供给/生成来源和输入干湿区报告计数、均值、标准差及饱和比例。干湿区定义为输入雨量 patch 内是否出现值 >=.1；这是当前未零中心化输入空间的诊断，不用未来目标指导门控。空组均值记 0，必须同时查看计数。另记录裁剪前门控范数、共享 patch 权重各任务梯度范数/余弦以及各时效使用的 q。

图片显示雷达、卫星第 0 通道和降雨的原始张量，nearest 插值，不额外模糊；同模态 history/prediction/truth 共用色标，雨量色标由该样本 history/truth 确定。卫星灰度单通道图与旧 RGB 合成图不是同一种显示方式。指标不从图片计算。验证使用当前模型，未改为 EMA 模型。

## 已知限制与后续实验

原 3D decoder 的 reflect 时间填充/跨时间归一化因果性问题、teacher forcing 解码 7 帧与 rollout 解码 1 帧的差异均保持原样。这是用户明确的结构边界，不能称为已修复，也限制最终性能归因。

首版只支持单设备 FP32/BF16，明确拒绝 FP16 scaler 和多设备。checkpoint 恢复模型/optimizer/scheduler/controller，但未保存数据迭代器精确游标；相同后续输入的更新已测试，不承诺整个数据顺序完全重放。

事件损失、演变损失、梯度自适应多任务权重保持后续消融项。当前 .1 辅助系数、.2 rollout 系数及 q 超参数是可验证起点，不是最优性结论。服务器建议按 [操作步骤](../experiments/2026-10-19-rain-priority-num8.md) 执行 smoke、A/E 短对照，必要时完成 B/C/D/F 消融后再决定长跑。
