# Stage 3 baseline integration

Goal: integrate the supplied final source and YAML with Persistence/LK and a common evaluator.
Architecture: an isolated copy of the supplied src, unchanged byte for byte; extensions live in src/baselines_stage3. Run from this project root. No runtime replacement of original methods and no file deletion.
Spec: user confirmed the first historical frame is fully observed; subsequent historical frames independently use full modalities with probability 0.6 or one of six other nonempty combinations with probability 0.4/6. Latest user instruction explicitly requires future GT radar/satellite updates, detach_rain_anchor=false, inherited loss weights, and 70000 optimizer steps.

## Decisions

- Use an isolated project directory because the supplied base trainer differs from the existing local trainer. Replacing existing source is prohibited by project instructions.
- The new task is observation-updated forecasting, not the earlier history-only experiment. Reports explicitly record reference access to progressively arriving radar/satellite and classical access to rain history only.
- Sparse LK uses the last two observed rainfall frames, scales velocity by their actual interval, and extrapolates from the last observation through the missing-history gap. Complete histories retain the four-frame LK estimator. One observation uses explicit zero-motion persistence, counted in reports.
- Fixed suffix scenarios still have a fully observed first frame; they are not strict satellite-only NPM experiments.
- Runtime dependencies are installed in the existing training environment; the ZIP does not contain datasets or pretrained weights. Original Stage 2 initialization path remains configurable and required for Stage 3 training.
- No Git actions: current environment reports no Git repository. User-authorized implementation proceeds directly in the isolated directory.
